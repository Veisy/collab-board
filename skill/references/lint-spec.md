# Lint specification

`node "$SKILL/scripts/collab-board.mjs" lint --session <id>` (or `--all`; `$SKILL` = the
installed skill directory, run from the project root) is **read-only**. It
recomputes the denormalized fields it can derive - hand-state, phase, `SEQ`, session status, the
four gates, and point status - from `log.md`, and checks the rest against its authoritative source.
The cursor (`TURN_CURSOR`/`RESPONDS_TO`/`NEXT_TURN_ID`/`NEXT_ACTOR`) is NOT projected. It prints one line per
finding — `PASS`, `WARN <code> ...`, or `FAIL <code> ...` — exiting non-zero if any `FAIL`.
Run it after **every** turn (especially each secondary delegation) and before any
phase/terminal transition. `--quick` skips the full-log projection (L2) for hot-loop use.

To resolve ONE finding, run `explain <code>` instead of reading this file: it prints that check's
row plus the remediation paragraph, so a single code costs a fraction of the whole spec. This file
is the complete set, for changing a check rather than for clearing one.

Authoritative sources, by field:

- hand-state, phase, cursor, gates → `HEAD.md` (and re-derivable from `log.md` via L2)
- point statuses / open count → `points.md`
- impl metadata → `impl/code_state.md` + the impl shard
- contract → `SESSION.md`

| Code | Severity | Rule | Checks |
|------|----------|------|--------|
| L0 PRECONDITION | FAIL | — | The session directory has no `HEAD.md` — there is nothing to verify, so lint reports this and stops (no other checks run for that session). |
| L0 STRUCTURE | FAIL | 2 | A board DIRECTORY (`turns/`, `agents/`, `plan/`, `impl/`) that exists but is not a directory, or a board artifact that exists but is not a regular file (a directory named `points.md` used to end the run with `EISDIR` and report nothing), or any structured board file carrying an UNCLOSED `<!--` comment. An unclosed comment masks to end of file, so it hides nothing today and swallows whatever is written next — an event appended after one vanished from every replay while `HEAD` and the log silently diverged. Comment markers inside inline code spans and fenced blocks are literal text, not syntax: these documents describe a Markdown format and quote `<!--` constantly. |
| L0 NESTED-COMMENT | FAIL/WARN | 2 | A `<!--` opened INSIDE an open comment, in `log.md`, `SESSION.md` or `plan/context.md`. Comments do not nest: the first `-->` ends the span, so a declaration behind the inner opener is read by nobody while the trailing closer is ordinary prose. Scoped to those three files because they are the ones where a vanished declaration is read as a VALUE rather than reported — an unreplayed event, an absent `Converge:` read as the defaults, a masked `STATUS: EMPTY` that no longer blocks the phase gate. HEAD, `points.md`, `impl/code_state.md` and the turn shards are OUT: there the loss is reported by its own consumer (L1/L2, L2/L4, L6, L13) under a diagnostic naming what went missing. Both bounds came from constructed inputs, not from reasoning: the board-wide form failed a legitimate review shard that QUOTED the exploit, and the log-only form missed the session and plan cases.
| L1 SPLIT-STATE | FAIL | 1 | Everything that makes `HEAD.md ## State` the ONE place hand-state lives, and the actors it names the ones the contract named. **Stray declarations:** a full assignment `- <ACTOR>: <HAND> - <ROLE>` in any file other than `HEAD.md`, or inside `HEAD.md` but OUTSIDE its `## State` section — `parseHead` does not read the latter as a row, so it is a declaration nothing acts on. (Anchored on the trailing ` - <ROLE>`, so prose bullets, `SELF_HAND:` mirrors and turn `Handoff` lines do not match.) **Section count:** any number of live `## State` sections other than exactly one — two sections are two truths, and `parseHead` reads only the first. **Actors:** the same actor named twice (PRIMARY and SECONDARY must be distinct), or a name outside `[A-Za-z0-9_]+`. **Keys:** an authoritative `HEAD` key declared more than once — only the first is read, so a second is a value that silently does nothing. **Identity:** `HEAD.md ## State` assigning a role to an actor that `SESSION.md` `Roles:` does not — the contract names the actors and `HEAD` carries their live state, so a board whose two answers differ has no single answer, and the mutating commands refuse to write under it. |
| L2 PROJECTION | FAIL | 1,4 | Replay `log.md` (OPEN/STATE_SET/HANDOFF/STALL_HANDOFF/GATE_SET/PHASE_SET/TERMINAL) → recompute hands, phase, gates, SEQ → assert equal to `HEAD.md`. `STALL_HANDOFF` flips the stalled actor to `ON_HOLD` and the `next=` actor to `START` (it carries `seq=`, like a handoff), so a Rule 5 recovery replays cleanly. Divergence means `HEAD` is corrupt; the log wins. Replay reads only the machine tokens each event declares (`<ACTOR>=<hand>`, `<ACTOR>:<from>-><to>`, `seq=<n>`, `stalled=`, `next=`, a leading `<GATE>=YES`); anything else on the line is not consulted, and a `PHASE_SET` that is not the one documented `PLAN->IMPL plan_open_points=<n>` form is a FAIL rather than a silent phase change (the projector matched only a PREFIX of it, so any trailing text advanced the phase). `POINT_SET` is parsed as a WHOLE LINE, like `PHASE_SET` and `SCHEMA_SET`: `<id>=<STATUS>` pairs and at most one `in=<turn-id>`, nothing else — reading the fragments it recognised and ignoring the rest let trailing text ride along unchecked. Ids within one `POINT_SET` must be DISTINCT, and `PHASE_SET`’s count must be `0`. A `POINT_SET` that moves any point to a non-`OPEN` status must carry `in=`, and the turn it names must exist as a `TURN_COMMIT` or a shard; the `Resolved In` cell is parsed as a whole link, so its DESTINATION must be the resolving turn’s own shard and not merely carry a label that agrees: without the first the projection records a resolved point with no resolving turn, and without the second `in=P999` stands as a resolver that was never written. L2 also reconciles `points.md` against the log: the UNION of projected and tabled ids, comparing Status AND `Resolved In`, so a table-only row, a wrong status, or a stale resolving turn each FAIL. A point is resolved by the TRANSITION that set its status, not by a later turn re-asserting it. Skipped under `--quick`. |
| L3 DUAL-START | FAIL / WARN | 4 | While `SESSION_STATUS=ACTIVE`, exactly one hand is in {START,WORKING}; hand tokens are valid; `NEXT_ACTOR` equals that holder. Also emits a **WARN** (advisory) if an `IDLE` session has any `START`/`WORKING` hand. |
| L4 PLAN-GATE | FAIL | 3,10 | `PLAN_OPEN_POINTS` equals the actual count of `OPEN` `P*` rows. Rows are read from the LIVE view: a row inside a comment is not a row, and reading raw here meant commenting a point out still COUNTED it as OPEN. If `PHASE=IMPL`: that count is 0, both `PLAN_AGREE_*=YES`, and `plan/context.md` exists and does not carry a line reading `STATUS: EMPTY`. That absence is the WHOLE enforcement — lint cannot tell a frozen plan from a placeholder that merely deleted the marker, so "a real digest" is a protocol obligation on the PRIMARY, not something this check verifies. Also: any `\| <id> \|`-shaped point row that fails to parse cleanly (e.g. missing trailing pipe) is a FAIL — an unparseable OPEN point must never be silently treated as resolved. A cleanly-parsed row whose `Status` is outside the closed set (`OPEN`/`AGREED`/`REJECTED`/`OUT_OF_SCOPE`) is likewise a FAIL — which now includes the retired `DEFERRED`. A board may not park work it needs: a postponement reads to every gate as a settlement, and `cmdAdvance` filtered on `OPEN` alone, so a board could cross into IMPL and reach `COMPLETED` carrying needed-but-undone work with lint PASSing throughout. Two boards in the recorded corpus did exactly that. `OUT_OF_SCOPE` covers work DETERMINED not to be needed; work that is needed is resolved here or carried to a successor board. **Archive ownership:** a point with a row in BOTH `points.md` and `points-archive.md` FAILs (every decision reads the two together, so a duplicated id makes that union ambiguous), and an OPEN row in the archive FAILs (the archive is for settled work; unfinished work stays where every turn reads it). |
| L5 IMPL-BEFORE-GATE | FAIL | 3 | Any `I*` turn shard **or** any `I*` `TURN_COMMIT` exists but there is no `PHASE_SET` in the log. Both halves are checked: reading shard filenames alone let IMPL work that was committed but whose shard was absent pass the gate check. |
| L6 IMPL-AUTHORITY | FAIL | 7 | Rule 7: only the PRIMARY authors code, and its shard must ECHO the recorded state rather than assert its own. **Authority:** a SECONDARY impl turn carrying a real `BRANCH` or `LATEST_COMMIT` (the markers that it authored code — a review-only turn omits the `Impl:` line entirely). **Placeholders:** a PRIMARY impl turn leaving any of `BRANCH`/`BASE_COMMIT`/`LATEST_COMMIT` at the `—`/`-` placeholder, in `impl/code_state.md` or in the shard. The literal `NONE` is a VALID "no git / not tracked" value — a non-git repo, or before the first commit — and passes. **Echo:** a PRIMARY impl shard whose `Impl:` values disagree with `impl/code_state.md`; the shard restates the singleton, and two disagreeing records of the same commit are not a record. **Cardinality:** a PRIMARY impl shard with zero or several `Impl:` lines (exactly one), or `impl/code_state.md` declaring a key more than once. **Role:** a turn whose actor `HEAD.md` declares no role for — every role-conditional check above silently does nothing for an actor it cannot classify, so the unclassifiable actor is the finding. |
| L7 CONTRACT | FAIL | 2 | `P1` exists but `SESSION.md` still has `Topic`/`Goal`/`Done` = `—`. |
| L8 ACK | WARN | 2 | The secondary's first turn shard contains no whole-word `ACK` anywhere in the file. It is a token search, not a reading: it cannot tell an acknowledgement from the word appearing in prose, and it looks at the whole shard rather than the body specifically. |
| L9 STALL | WARN | 5 | `now − LAST_UPDATE > CHECK` **and `HEAD.STALL_STATE` is `OK`** → WARN (an actor that already recorded a stall state suppresses the repeat WARN); `> CHECK+HANDOFF` with no `STALL_HANDOFF` logged → WARN regardless of `STALL_STATE` (advisory only — a paused-but-healthy board must not hard-FAIL; if the owed actor is truly silent, log `STALL_HANDOFF` and force the handoff). Timers from `SESSION.Stall`. |
| L10 DEADLOCK | FAIL | 6 | A point still `OPEN` with more than 3 `TURN_COMMIT`s referencing it and no `DECISION` line. Fires the moment the threshold is crossed — typically right after a secondary turn commits. It is the Rule 6 forcing signal, not board corruption: the expected recovery is that the PRIMARY resolves the point (or logs a `DECISION`) on its very next turn, which clears the FAIL. **Routing:** a `FAIL` set that is *entirely* `L10` is not a correction case — the landed SECONDARY turn is kept and the PRIMARY decides on its next turn; any mixed or non-`L10` `FAIL` follows correction recovery. `L10` remains blocking either way: no phase or terminal transition until it clears. Resume-lineage routing lives in `recovery.md`. |
| L11 TERMINAL | FAIL/WARN | 8 | `SESSION_STATUS` terminal but both hands ≠ `DONE`; or a `TURN_COMMIT`/`HANDOFF` logged after the `TERMINAL` line; or `SESSION_STATUS=COMPLETED` without (`PHASE=IMPL` and both `IMPL_AGREE_*=YES`) — the completion gate. **Open points at COMPLETED (FAIL):** `SESSION_STATUS=COMPLETED` while any point is still `OPEN`. COMPLETED asserts the work is DONE, and this gate never read `points.md` at all — so a board could complete carrying every `I*` raised during IMPL, which `advance` never sees because it checks `P*` at the PLAN gate only. `cmdTerminal` refuses at write time and this reports at read time, since a board hand-edited to COMPLETED reads as finished to every later session unless lint says otherwise. `ABORTED` is exempt: stopping early is an honest end. What it CANNOT check is whether the work a RESOLVED point describes was actually done — which is why `DECISION` carries direction and status carries delivery. |
| L12 ESCALATION | WARN | 9 | Fewer `USER_QUESTION` log events than turn shards containing the literal `USER_QUESTION:`. The two are COUNTED, not matched — a shard is counted once however many questions it contains, so this detects a missing log line in aggregate and cannot say which question is unlogged. |
| L13 TURN-SCHEMA | FAIL | turn fmt | A `turns/*.md` shard is missing a required line (heading, `Header`, `Body`, `Evidence`, `Handoff`, `PREV:`, `NEXT:`); a PRIMARY IMPL shard missing its `Impl:` line (which must start at column 0 — an indented copy nested inside `Body` does not count). |
| L14 CHAIN/ORPHAN | FAIL | §3 | Every shard has a matching `TURN_COMMIT` and vice-versa (an orphan = crash mid-turn); `HEAD.RESPONDS_TO` resolves; and each shard's `PREV` **and** `NEXT` link target exists (`NEW` / `pending` excepted). The `NEXT` check is symmetric with `PREV` and catches a write-order regression — a predecessor's `NEXT` flipped to a link before the successor shard exists (a dangling forward pointer). **One root (FAIL):** two or more shards declaring `PREV: NEW`. `NEW` means "no predecessor", so a second one declares a second beginning and the turns have no derivable order — while every `PREV`/`NEXT` target still resolves, so the link checks above pass and nothing else notices. The scoped prompt hands a secondary the literal string `PREV: NEW` to fill in, and `relay` used to let a capture's own value stand, so this is the ordinary accident rather than an exotic one. |
| L15 MIRROR-DRIFT | WARN | 1 | `agents/<a>.md` `SELF_HAND` ≠ that actor's hand in `HEAD.md`, for an actor **not** at `START` or `DONE`. Both are skipped because their mirrors are legitimately stale: a `START`-holder set `SELF_HAND=ON_HOLD` ending its last turn and hasn't acted yet, and a `DONE` actor was flipped by `terminal` (an engine action, not a turn — and a terminated session takes no more turns, so the drift is moot). L3 guarantees at most one `START` holder, so a genuine stale mirror on an ON_HOLD/WORKING actor is still caught. |
| L16 CATALOG-SYNC | WARN | catalog | The `index.md` row for this session disagrees with `HEAD` on Status/Phase, **or there is no row for the session at all** — a catalog that never learned about a board cannot disagree with it, so the missing-row case has to be named separately or it reads as agreement. Reconciled to `ACTIVE` by `activate` on the first turn, and by `advance`/`terminal`/`reset` thereafter. |
| L18 CLI-EXECUTOR | FAIL | adapter | `SecondaryAdapter` is outside the closed set (`codex-cli`, `claude-cli`, `copilot-cli`, `agy-cli`, `omp-cli`, `reasonix-cli`, `manual`, non-empty `subagent:<name>`, or stored legacy `codex`), or a CLI executor names a secondary outside the actor FAMILY it drives: `codex-cli`/`codex` requires `SECONDARY=CODEX` or a `CODEX_*` family name; `claude-cli` requires `SECONDARY=CLAUDE` or `CLAUDE_*`; `copilot-cli` requires `SECONDARY=COPILOT` or `COPILOT_*`; `agy-cli` requires `SECONDARY=ANTIGRAVITY` or `ANTIGRAVITY_*`; `omp-cli` requires `SECONDARY=OMP` or `OMP_*`; `reasonix-cli` requires `SECONDARY=REASONIX` or `REASONIX_*`. Membership is a prefix **plus a separator** (`CLAUDE_2` is in the family, `CLAUDEX` is not) — a bare prefix match is the defect class that once let `PLAN_AGREE_PRIMARY=YESTERDAY` set a gate. **This row is about ACTORS, never MODELS.** It relates ONE actor to ITS OWN adapter and never compares two actors' models, so it explicitly PERMITS the same model in both seats (`PRIMARY=CLAUDE` with `SECONDARY=CLAUDE_2`), which is how a board stays usable when only one model is available — no mode, no extra key, no lint code spent. What it still catches is a naming lie: `--secondary CODEX --adapter claude-cli` remains a FAIL. The set and the pairings are derived in the engine from one table and this row is checked against that table by the self-test, so an executor cannot ship without appearing here — which it did, twice, on 2026-08-04. **Panel (FAIL):** a `SecondaryPanel` that is not two or more DISTINCT CLI executors from that same set, or one declared without `BoardWriteMode: PRIMARY_ONLY` — several executors cannot each write the same turn, so a panel board must be sole-writer. With a valid panel the pairing rule above does not apply: no single executor owns the SECONDARY role. |
| L19 EVIDENCE-ON-RESOLVE | WARN | evidence | A turn that **resolves** a point (a `POINT_SET` to a non-`OPEN` status in the log) has a `- Evidence:` line at the start of a line whose inline value is exactly `N/A` (case-insensitive). A turn with no `- Evidence:` line at all, or one whose evidence is present but worthless, is NOT flagged — this is a single-token check, not an assessment. Advisory only (never FAIL): a resolved decision should cite resolvable evidence (`file:line`, command/test output, doc/URL). Whether a claim is "disputed" is prose guidance, not lintable — L19 flags only the explicit empty-evidence token, never judges content. Reinforces "challenge and ask with evidence"; mutual agreement is not verification. |
| L20 GATE-AUTHORSHIP | FAIL/WARN | 10 | Each gate is set by its own actor. **Forged:** a `GATE_SET` whose `by=<ACTOR>` disagrees with the gate's role suffix (`*_PRIMARY`/`*_SECONDARY`) — one actor flipping the other's agreement. **Unattributed:** a `GATE_SET` carrying no `by=` at all, which is a separate case because the projector APPLIES any recognised `GATE_SET`, so an authorless gate was projected as agreement that nobody had given. This is the machine-checkable half of the §4 anti-rubber-stamp norm (`justified_by=`/`relayed_by=` are deliberately not matched — the first records why, the second records who transcribed). **Ruleset-gated (dead end):** this finding names immutable history — an append cannot suppress it, indenting keeps it selected, and commenting it out is itself a finding. It FAILs a board whose `OPEN` declares the ruleset that introduced it and WARNs a board that declares none, so a legacy board is told rather than blocked. Malformed provenance FAILs and is resolved to the current ruleset, so a misspelling cannot buy the exemption. **Provenance:** the optional `verified=self|reported` token records whether the gate's actor RAN the check it cites (`self`) or relied on another actor's result (`reported`); absence means no executable check applied and is never a finding. The token FAILs when its value is neither word, when it carries no `justified_by=<turn-id>`, when that turn has no shard, or when that shard's `- Evidence:` is absent or literally `N/A` — a self-verification claim with nothing underneath it. Grammar, linkage and the presence of evidence are checkable; whether the command was really run is not, and a check that pretended otherwise would be the rubber stamp the token exists to remove. Dead-end and ruleset-gated on the same terms as the arms above. |
| L21 ENCODING | WARN | encoding | A board file (`HEAD`/`SESSION`/`points`/`log`/`plan/context`/`impl/code_state`/`agents/*`/`turns/*`) begins with a UTF-8 **BOM** (`EF BB BF`), or contains a **cp1252 double-encoding mojibake run** (`0xC3 0x82`/`0xC3 0xA2` followed by another high byte — e.g. `â€`). A raw byte-scan, not a text decode; `readText` itself strips a leading BOM before parsing. WARN-only — an encoding-hygiene issue must never block an otherwise-valid turn, and the mojibake sentinel requires the trailing high byte so a legitimate accented letter (`é`=`C3 A9`) does not trip it. A model turn or an external editor can introduce either and it would otherwise pass lint silently; re-save as clean UTF-8 (no BOM). |
| L22 MERGED-LOG-LINE | FAIL/WARN | §8 | A `log.md` line embeds 2+ ISO-8601 timestamps — two events merged onto one line because a prior append lacked a trailing newline. `parseLog` still matches such a line (the first event's type wins), so the second event silently vanishes from every replay; L22 catches the merge that L2/L14 can otherwise miss (a merged `POINT_SET`/`DECISION` touches no field they compare). No §8 event carries a bare timestamp as a field value, so the 2-timestamp signature is false-positive-free within the closed grammar (header/comment lines carry none). The engine's `appendEvent` prevents the merge at every engine append site; L22 is the backstop for a hand-edit or a future writer. **Closed vocabulary (FAIL):** an event whose type is not one of the §8 types (`OPEN`, `STATE_SET`, `TURN_COMMIT`, `POINT_SET`, `GATE_SET`, `PHASE_SET`, `HANDOFF`, `STALL_CHECK`, `STALL_HANDOFF`, `DECISION`, `USER_QUESTION`, `TERMINAL`, `SCHEMA_SET`, `REFRAME`). §8 called the vocabulary closed while `parseLog` accepted any word and every projector ignored what it did not recognise, so a misspelling dropped a real event out of every replay with no finding at all. The whole line is quoted in the diagnostic, because the type is usually one character from a type that would have applied. The SELECTOR is "begins with a timestamp", not "parses as an event": a line that claims to be an event and fails the grammar FAILs too, since recognising events by whether they match let a line one character off be invisible to every check. **Commented events (FAIL):** an event line inside a comment. The log is append-only — an event is recorded or absent, never commented out — and every projector used to replay such a line, so a commented `TERMINAL` ended a live session's projected state. |
| L22 CLOSED-VOCABULARY | FAIL/WARN | §8 | A `log.md` line that BEGINS with a timestamp but is not an event, or whose event type is not in §8. Judged whether or not it parses: a line one character off the grammar was previously not an event to any check, so it recorded state no projector replays. **Ruleset-gated (dead end):** an append cannot suppress it, indenting keeps it selected, and commenting it out is itself a finding — so it FAILs a board declaring the ruleset that introduced it and WARNs one declaring none. Malformed provenance FAILs and resolves to the current ruleset, so a misspelling cannot buy the exemption. |
| L22 COMMENTED-EVENT | FAIL/WARN | §8 | An event line inside a comment. The log is append-only and an event is either recorded or absent, never commented out; every projector used to replay one, so a commented `TERMINAL` ended a live session's projected state. Detected over COMMENT SPANS rather than raw lines, with the same anchored selector the live path uses: a scan of the raw line saw only block comments, and an inline `<!-- … -->` wrapper hid the event from this check and from CLOSED-VOCABULARY both. Anchoring at the payload line's logical start is what separates a record from a QUOTATION, so a comment quoting the grammar stays silent. |
| L23 LOG-TIMESTAMP-ORDER | FAIL/WARN | §8 | **Real instants (FAIL):** an event timestamp that is not a genuine RFC3339 instant — shaped like one but impossible (`2026-99-99T99:99:99Z`) or calendar-invalid (`2026-02-30`, which `Date.parse` silently rolls into March). Every ordering comparison against `NaN` is false in both directions, so such a line used to order nothing and report nothing; it is now checked before it is compared. **Ordering:** parsed log event timestamps decrease, or a log event / `HEAD.LAST_UPDATE` is more than 60 seconds ahead of the host clock. Equal timestamps stay valid for legacy boards; later events may not be earlier. For a shell-free secondary, PRIMARY supplies `DISPATCH_UTC = max(host UTC, HEAD.LAST_UPDATE + 1 ms)` and the turn uses ordered millisecond offsets. A failure can also diagnose `STALL_CHECK` racing a late-landing dispatched turn — that near-double-writer overlap should be surfaced, not suppressed. The engine's `appendEvent` clamps its own second-precision stamp to the log's last event time when the gap is under one second (the truncation artifact; equality is valid) — a larger decrease is written as-is so L23 still surfaces the earlier wrong-time event. |
| L24 ACTOR-NOTES | FAIL / WARN | §3 | Everything about `agents/`. **File set (FAIL):** an actor in `HEAD.md ## State` with no actor file, a file in `agents/` matching no actor, or an entry there that is not a regular file — `agents/` holds one actor file per actor and nothing else, and the check is on the SET rather than on names ending `.md`, since a stray file is litter whatever it is called. **Applicability (FAIL):** which grammar applies comes from the board's log PROVENANCE (`OPEN ... agent_schema=<v>`, then any `SCHEMA_SET`), never from the actor file's own `SCHEMA:` line — resolving it from the file let a v2 file rewrite that line to v1, delete all five mandatory keys, and lint clean. Where provenance exists the file must declare the matching version; declaring the other one, or none, FAILs. Malformed provenance FAILs rather than reading as absence, or the malformed spelling becomes the escape. Provenance itself is constrained: `SCHEMA_SET` is one-way along the declared edges only (`agent/v1->agent/v2`, `agent/v2->agent/v3`), must follow the board's current schema, must be authored by the board's PRIMARY, and only one `OPEN` may declare `agent_schema=`. Without those, appending `SCHEMA_SET agent/v2->agent/v1 by=<anyone>` demoted a board and let both actor files drop every mandatory key — the escape re-opened one level up. `migrate` decides "already at the target version" with the SAME validator this row describes; when they were two implementations, migrate skipped a file lint rejected and committed a board that failed its own next lint. A log with no such event is a LEGACY board: it is never retroactively failed on a closed grammar, its file's own declaration still selects the grammar, and lint WARNs that the grammar is therefore still file-selected and names `migrate` as the fix. **Grammar (per declared version, FAIL):** `agent/v3` has exactly three mandatory keys — `ACTIVE_RECOVERY`, `EXECUTOR_THREAD`, `UNRESOLVED_CONCERNS`; `agent/v2` has those same three preceded by `SELF_HAND` and `LAST_TURN_WRITTEN`, the two HEAD mirrors v3 drops; `agent/v1` declares no closed grammar. The version's keys appear in that order, once each, on consecutive top-level lines before the `PRIVATE_NOTES:` delimiter; only the title, `SCHEMA:`, blank lines and comments may accompany them. The grammar is CLOSED: unknown, missing, duplicate or malformed keys FAIL. Every key has an explicit parseable `NONE`, so a key is never deleted. `UNRESOLVED_CONCERNS` holds `<point-id>@<pointer>` pairs ONLY (pointer must end `.md`, optional `#fragment`, no absolute path, no `..`) — never prose, which is precisely the relabeling escape this shuts. **Size ladder (every version):** the DISCRETIONARY region — every raw byte after the `PRIVATE_NOTES:` marker line's LF — WARNs above 8,192 B and FAILs above 16,384 B, counted in raw file bytes so CRLF and multibyte cost is charged. Mandatory/header bytes are EXCLUDED, so an actor mid-recovery is never pushed to drop the fields that make recovery possible. Thresholds: 8,192 B is CHOSEN (early warning); 16,384 B is DERIVED as 2× that target and sits above every recorded actor file except the known 44,336 B runaway. Legacy `v1` gets the ladder but never a retroactive grammar failure — existing boards stay readable and migrate explicitly, never implicitly. Overflow is NON-TRUNCATING: move settled prose to the current shard or `points.md` and leave an `id@pointer`; if no durable destination exists, keep the content and accept the visible finding. |
| L25 PRIMARY-RELAY | FAIL | §3 | Applies ONLY to a session whose `SESSION.md` declares `BoardWriteMode: PRIMARY_ONLY`; a board without that key is untouched by this check and pays nothing. Under the mode the SECONDARY never writes the board, so every SECONDARY `TURN_COMMIT` must carry `relayed_by=<PRIMARY>` — an unrelayed secondary turn means something wrote the board that was not supposed to. It must also carry a well-formed `attempt=<n>`, which is what distinguishes a retried relay from a duplicated one, and a `capture_sha=<hex>` that some retained file under `captures/` actually hashes to. The capture is the fidelity record: without the sha binding, a relayed shard cannot be checked against the output it came from, and an edited or absent capture would be indistinguishable from an honest one. **Fusion (FAIL):** a `TURN_COMMIT` declaring `fused=yes` whose shard does not name every retained contributor, or whose `contributors=<n>` disagrees with the number of captures retained for that turn. The check keys on the DECLARED token rather than on how many captures survive on disk, so deleting a capture cannot switch off a check about dropped contributors. **Orphaned captures (FAIL):** captures retained under `captures/` for a turn id with no `TURN_COMMIT` — a relay that died between retaining the evidence (its first write) and committing the turn. The per-`TURN_COMMIT` loop above is structurally blind to this: the board shows `captures/` populated, `turns/` empty, and lint PASS. **Remediation, in general:** a `FAIL` means a write step was skipped or done out of order.
Because `HEAD.md` is written last and the `HANDOFF` log line is the commit point (for a final
PRIMARY turn, the `TERMINAL` line), an
incomplete turn is recoverable: either complete the missing writes (then re-lint) or, for an
orphan shard with no `HANDOFF`, delete the orphan and re-delegate the turn. Never paper over a
projection (L2) mismatch by editing `HEAD` to match a wrong assumption — reconcile against the
log, which is the immutable derivation.
